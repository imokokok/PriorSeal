# Database operations

Production uses Cloudflare D1 `priorseal-production` through the Worker's `DB` binding. Its forward-only SQL migrations live in `d1/migrations/`; review them and apply with `wrangler d1 migrations apply priorseal-production --remote` before deploying code that needs them. `wrangler d1 migrations list priorseal-production --remote` should report no pending migrations. D1 stores the authorization/Merkle log, durable jobs, receipts, idempotency records, and the scoped evidence archive. Export and test a restore regularly; D1 exports and Time Travel are the production recovery sources.

The PostgreSQL path remains for the separate local Node runtime. Apply its SQL files in lexical order inside a transaction using a least-privileged migration role. Put a direct PostgreSQL connection string in `DATABASE_URL_UNPOOLED` and run `npm run db:migrate`; the Node application uses pooled `DATABASE_URL`. Migrations are forward-only; do not edit an applied file. `008_observation_job_leases.sql` adds recoverable job leases and `010_authorization_merkle_index.sql` creates and backfills the compact-proof index. These PostgreSQL migrations do not apply to D1.

The D1 initial migration includes the project/environment-scoped uploaded-evidence archive. On the PostgreSQL path, `009_project_evidence_archive.sql` adds it separately. Enable archive credentials only after the applicable schema is ready; see [archive access, retention and validation](project-evidence-archive.md).

Back up D1 and test a restore to an isolated database at least quarterly. Verify counts, full-row hashes, foreign keys, and receipt signatures against the published key registry before switching traffic. Keep a protected D1 export under the operator's retention policy and verify the available Time Travel window before relying on it. Retain observations and receipts according to audit policy; expiry cleanup applies only to idempotency records after their TTL.

The D1 Worker atomically claims due jobs with `UPDATE ... RETURNING` and a 15-minute lease, so the delivery contract remains at-least-once. Expired `RUNNING` leases are recoverable, and stale workers cannot update a job after a new owner claims it. Consumers must keep receipt/observation writes idempotent. Investigate `FAILED` jobs, correct the cause, then explicitly requeue with a new idempotency key or audited state transition. The local PostgreSQL adapter uses `FOR UPDATE SKIP LOCKED` for the same contract.
