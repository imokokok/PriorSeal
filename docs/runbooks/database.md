# Database operations

Production uses Cloudflare D1 `priorseal-production` through the Worker's `DB` binding. Its forward-only SQL migrations live in `d1/migrations/`; review them and apply with `wrangler d1 migrations apply priorseal-production --remote` before deploying code that needs them. `wrangler d1 migrations list priorseal-production --remote` should report no pending migrations. Migration 0011 records the Worker runtime schema capability only after all earlier D1 migrations have applied; migration 0012 advances that capability to 12 and adds the archive R2 index and outbox. Apply a future structure migration before activating code that requires its advanced capability. D1 stores the authorization/Merkle log, durable jobs, receipts, idempotency records, the scoped archive index, and, by default, original archive artifact bytes in `entry_json`. When the optional R2 binding is configured, artifact bytes move to R2 and D1 keeps only the index and the reconciliation outbox. Export and test a restore regularly; D1 exports and Time Travel are the production recovery sources.

The PostgreSQL path remains for the separate local Node runtime. Apply its SQL files in lexical order inside a transaction using a least-privileged migration role. Put a direct PostgreSQL connection string in `DATABASE_URL_UNPOOLED` and run `npm run db:migrate`; the Node application uses pooled `DATABASE_URL`. Migrations are forward-only; do not edit an applied file. `008_observation_job_leases.sql` adds recoverable job leases and `010_authorization_merkle_index.sql` creates and backfills the compact-proof index. These PostgreSQL migrations do not apply to D1.

The D1 initial migration includes the project/environment-scoped uploaded-evidence archive table; migration 0012 adds the optional R2 index columns and the orphan-reconciliation outbox. Artifact bytes remain in D1 unless the R2 binding is configured, in which case only the content-addressed index stays in D1. On the PostgreSQL path, `009_project_evidence_archive.sql` adds the archive separately and artifacts remain in PostgreSQL. Enable archive credentials only after the applicable schema is ready; see [archive access, retention and validation](project-evidence-archive.md).

Back up D1 and test a restore to an isolated database at least quarterly. Verify counts, full-row hashes, foreign keys, and receipt signatures against the published key registry before switching traffic. Keep a protected D1 export under the operator's retention policy and verify the available Time Travel window before relying on it. Retain observations and receipts according to audit policy; expiry cleanup applies only to idempotency records after their TTL.

The D1 Worker atomically claims due jobs with `UPDATE ... RETURNING` and a 15-minute lease, so the delivery contract remains at-least-once. Expired `RUNNING` leases are recoverable, and stale workers cannot update a job after a new owner claims it. Consumers must keep receipt/observation writes idempotent. Investigate `FAILED` jobs, correct the cause, then explicitly requeue with a new idempotency key or audited state transition. The local PostgreSQL adapter uses `FOR UPDATE SKIP LOCKED` for the same contract.

Queue prompts use a primary-key claim for their specific job; scheduled recovery keeps the bounded due-job scan. D1 Merkle append and inclusion-proof reads use a batch of indexed node lookups, retaining the same proof bytes and atomic append boundary. Archive queries bind only active filters so the existing project/transaction and project/authorization indexes can be used while preserving tenant scope and snapshot pagination. Archive artifact reads resolve only through the D1 index: `storage='d1'` rows are hash-verified from `entry_json`, and `storage='r2'` rows verify the object's size and SHA-256. A missing index is a 404 and is never repaired by scanning R2. Run the SQLite-backed D1 adapter tests on Node 22 or later; they exercise queries, transactions, proofs, and lease recovery without accessing the production database.
