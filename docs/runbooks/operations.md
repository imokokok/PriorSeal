# Operations runbook

Start locally: `cp .env.example .env.local`, configure only development RPC/key file paths, then run `npm ci`, `npm run start:api`, and `npm --prefix web run dev`. Use `GET /health/live` for process liveness and `/health/ready` for dependency readiness.

Before enabling signed authorization in a persistent environment, apply migrations through `007_observation_job_results.sql`, set a deployment-specific `PRIORSEAL_AUTHORIZATION_AUDIENCE`, and place the strict JSON authorization policy at `PRIORSEAL_POLICY_FILE`. Changing either audience or policy intentionally invalidates authorizations prepared for the previous deployment policy. Keep the policy file under change control and retain each published policy hash with audit evidence. When named identity matters, include entries such as `{ "id": "acme-treasury", "type": "organization", "account": "0x...", "authorizerType": "eip1271" }` in `policy.principals` only after the identity-to-account relationship has been reviewed through your onboarding process.

Set `PRIORSEAL_ENVIRONMENT=production`, an immutable `PRIORSEAL_BUILD_VERSION`, a deployment-specific `PRIORSEAL_KEY_ID`, and explicitly choose `PRIORSEAL_PREEXECUTION_PROOF_MODE=rfc3161`, `witness-quorum`, or `evm-anchor`. Production startup fails unless both database URLs, issuer keys, a non-default issuer and audience, a non-localhost CORS origin, a policy containing at least one reviewed principal, and all dependencies for the selected proof mode are configured. The example defaults to `rfc3161` and intentionally denies all principals and value transfers until reviewed values replace its empty lists and zero amount.

For the simplest no-Gas mode, include `{ "schema": "priorseal.timestamp-policy.v1", "profile": "digicert-rfc3161-v1", "maxClockSkewSeconds": 300 }` as `timestampPolicy`. No additional credential is required. PriorSeal submits only the authorization hash to DigiCert's [documented RFC 3161 endpoint](https://knowledge.digicert.com/general-information/rfc3161-compliant-time-stamp-authority-server) at `http://timestamp.digicert.com`; integrity and authenticity come from strict verification of the signed RFC 3161 response, not transport security. Treat TSA unavailability as fail-closed: an authorization is not accepted without a verified token. Monitor availability and pin changes through a reviewed software release rather than dynamically trusting response certificates.

For the Gas-free mode, add `witnessQuorum` to the signed policy with a threshold of at least two and a distinct Ed25519 public key for each operator. Keep the corresponding HTTPS URLs and bearer tokens in the secret-mounted `PRIORSEAL_WITNESS_ENDPOINTS_FILE`. Deploy each witness under a separate operator/account, give it its own database and key pair, apply migration 005 to that database, and start it with `npm run start:witness`. Confirm `/health/ready` and `/.well-known/priorseal-witness-key.json`, then compare the published key to the signed policy out of band. A policy/key change requires new user authorizations because it changes `policyHash`.

Run `npm run production:check` before a release. It performs non-mutating checks for the production configuration, immutable build version, issuer private-key permissions, reviewed principals, migration 007 and its durable observation-result column, evidence tables, RPC chain identities, and the selected proof-mode dependencies. A failed check blocks release.

The built-in authorization log is an issuer-signed, append-only hash chain. RFC 3161 mode adds an independent authority's signed time without a chain transaction; witness-quorum mode adds independently operated signatures. If EVM consensus is required instead, periodically anchor a signed checkpoint outside PriorSeal and provide the verified anchor record through `PRIORSEAL_TRANSPARENCY_ANCHOR_FILE`. EVM-anchor execution fails with `TRANSPARENCY_ANCHOR_REQUIRED` before consuming the authorization unless the configured, on-chain-verified anchor covers it. The reference `PriorSealTransparencyAnchor.sol` contract is unaudited; deploy it only after review, make its owner a reviewed multisig, and wait for the required finality.

After an audited anchor contract is deployed, set `PRIORSEAL_ANCHOR_CHAIN_ID` and `PRIORSEAL_ANCHOR_CONTRACT`. Run `npm run anchor:prepare` to produce public transaction calldata for the latest authorization-log head, submit that call from the external owner multisig, then set `PRIORSEAL_ANCHOR_TX_HASH` and run `npm run anchor:record`. The record command requires the configured confirmation threshold, checks chain ID, target, successful receipt, calldata, block and timestamp, and writes the public anchor record without handling a wallet private key. Restart or roll the service after updating the record, then call the authorization transparency endpoint before permitting the agent to execute.

When RPC failures rise, do not mark transactions failed. Check endpoint health/chain ID, rotate to a configured fallback, and replay affected jobs. For a reorg, retain the original receipt, re-observe after finality, issue a new receipt marked `REORGED`/superseding evidence, and notify relying systems.

For issuer-key rotation: place historical public keys in a public-only JSON file and set `PRIORSEAL_KEY_REGISTRY_FILE` to its path. The file shape is `{ "schema": "priorseal.keys.v1", "keys": [{ "issuer": "priorseal", "keyId": "old", "algorithm": "Ed25519", "publicKey": "-----BEGIN PUBLIC KEY-----...", "status": "retired", "validFrom": 1700000000, "validUntil": 1800000000 }] }`. Configure the new signing key under a new `PRIORSEAL_KEY_ID`; the active key is merged into the published registry. Never put private-key fields in this file. If an issuer key is compromised, mark it revoked, rotate immediately, preserve audit evidence, and disclose affected receipt time ranges.

For legacy RPC URL exposure: releases before the source-identifier fix could embed the entire configured endpoint in observations and signed receipts. Do not rewrite signed receipts because doing so invalidates their signatures. Immediately rotate any RPC credential embedded in a URL, update `PRIORSEAL_RPC_*`, restart the service, and stop distributing old receipt files until the credential is invalid. Unsigned observation rows may be access-restricted or removed only under the organization's evidence-retention policy.
