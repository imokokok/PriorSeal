# Insight + PriorSeal：RWA / 代币化股票改造验收

> 本页为首版历史验收记录；后续六项代码加固、v2 语义能力和最新边界见
> [RWA v2 加固说明](rwa-hardening.md)。以下首版计数及范围不代表最新工作区全绿。

验证日期：2026-09-20。结论：**本地工程实现及联合验证完成；生产交易能力未激活。**
改造采用独立、显式启用的协议，不以删除或改写原有 Agent / DeFi 能力换取 RWA 支持。

## 六阶段交付

1. **资产身份与报价口径**：底层标的、发行人、代币合约、结算链、交易场所、
   币种、价格口径和公司行动版本共同形成资产 ID。股票原价、代币市场价、
   NAV 不混算；证据链与结算链明确分开。
2. **按操作评估**：买卖、借款、抵押、清算、赎回和还款分别配置规则。
   支持交易时段、个股停牌、公司行动、报价时效、价差、多源独立性及发行人
   相关断言；未知必需信息不放行。还款可显式不依赖价格。
3. **独立签名报告**：新增 RWA v1 域与内容哈希，消费者固定策略和可信公钥，
   验证者重算结果；支持有效期、撤销、环境隔离及交易范围检查。
4. **使用入口**：Insight SDK、HTTP POST、MCP 工具、OpenAPI 和严格 JSON Schema；
   Chainlink 链上轮次及已认证解码的 v11 mid 报告适配器。HTTP/MCP 仅诊断，
   不对调用者提供的未经认证数据签生产证明。
5. **授权与回执**：PriorSeal 将授权时评估绑定到 exact-call，保留其他上下文承诺；
   执行前可要求独立的新评估；在回调入口核对实际 calldata、链、地址、金额、
   nonce 与有效期；联合验证签名回执、原始授权及两个评估。
6. **实际使用验证**：联合脚本直接加载两个构建后的 SDK，完成签名、主体授权、
   执行入口检查、模拟观察、回执签名和离线验证。失败案例确认未进入执行回调。

实现支持三种使用方式：Insight 独立评估、PriorSeal 独立授权/执行取证、
以及二者组合。没有要求现有客户迁移到 RWA。

## 兼容性与上线边界

旧 Pre-Trade、Watch、coverage、Agent guard、授权和回执格式未改写。
Insight 新增第 10 版协议推广记录，保留原有不可变推广记录、客户策略及
activation set，并列出全部现有已激活伙伴的兼容性说明。未替客户启用 RWA。

当前可以做工程接入、策略回放、本地验证和无资金影子评估；**不能据此宣传为
已生产可用的全品类 RWA 交易基础设施**。上线还需要：

1. 选定一个真实发行人/代币/交易场所及具体操作，核验身份和合约语义。
2. 采购或取得两组独立、可合法使用且满足时效要求的数据，认证原始报告；
   不能把已解码数据、供应商名字或 API 成功当作真实性证明。
3. 接入并评审个股停牌、公司行动、发行人储备/赎回和双方参与者资格来源。
   当前资格字段针对发送方；接收方、司法辖区等限制仍由业务与发行人控制。
4. 配置专用签名密钥、独立信任固定、撤销及轮换、监测告警和审计流程。
   签名时间依赖可信签名者；需要更强时序证明时继续使用既有时间戳/见证机制。
5. 保留原 Agent 风控、滑点/成交检查、原子 nonce/重放控制与链最终性检查，
   先影子运行，再经批准做限额试点和发布部署。

本次没有推送 Git、发布 npm 包、部署服务、开通付费数据或广播交易。
这些外部动作不是本地验收通过后的自动步骤。
