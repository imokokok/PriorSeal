# Monad zero-value exact call — recorded live run

Status: `PING_VERIFIED_ON_CHAIN` in the repository's read-only verifier on
2026-10-21 (Asia/Shanghai).

This is a public technical case record for the Monad + PriorSeal Ping v1
demonstration. It establishes an exact, principal-controlled, zero-native-value
call. It does **not** claim an Insight market-risk assessment, x402 settlement,
economic safety, token safety, or production custody.

The deployed [`MonadPriorSealPing`](../../contracts/MonadPriorSealPing.sol)
contract accepts only `record(bytes32)`, emits `RunRecorded`, and reverts if a
caller attaches native value. The exact call's principal authorization was an
EIP-712 PriorSeal authorization limited to this target, calldata hash, nonce,
zero value, and one use.

## Reproduction boundary

The transaction hashes, account, contract address, event, and zero values are
public chain facts. The original EIP-712 signature is intentionally not checked
into this repository, even though it is not a private key, so a third party
cannot reproduce the `signatureValid` assertion from this record alone.

An authorized evidence holder can repeat the full read-only check with the
original bundle and signature:

```sh
npm run monad:ping:verify -- \
  --bundle /absolute/path/to/bundle \
  --rpc https://your-monad-rpc.example \
  --deployment-tx 0x584eeaf5e06abf6e7bc984ad05d95f2b22b1226352f716d3169dc7131ac07147 \
  --call-tx 0x00d3069038aa03bbe14d5f181a6707167ff836bc230efd5cdb980f1f6ac2b338 \
  --signature 0xORIGINAL_EIP712_SIGNATURE \
  --out /absolute/path/to/new-verification-output
```
